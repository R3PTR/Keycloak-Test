How sign-in works here

  1. The form posts to /users/login (user-service).
  2. user-service asks Keycloak for tokens (password grant, confidential client).
  3. Keycloak looks the user up and checks the password by calling back into user-service through the User Storage SPI. Users live in user-service's PostgreSQL.
  4. The access token comes back to this page (kept in memory only). The refresh token is an HttpOnly cookie that JavaScript can't read.
  5. API calls send the access token; nginx verifies it via auth_request.
